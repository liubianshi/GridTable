This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this package does

`GridTable` is an R package that renders a `data.frame`/`data.table` (or a
`knitr::kable`) into a plain-text **pandoc grid table** — ASCII boxes drawn with
`+ | - = :`. It is CJK-width aware (uses `nchar(type = "width")` everywhere, via
`str_width()`), so tables containing Chinese/wide characters stay aligned. It
supports merged cells (colspan, rowspan, and both at once), header/footer
separator lines, per-column alignment, content wrapping, vertical centring, and
automatic column-width / row-height growth so content always fits.

The implementation is split across small files under `R/`:

| File | Responsibility |
|------|----------------|
| `api.R` | Exported constructors / mutators: `GridTable`, `kable_to_grid`, `merge_cells`, `set_attr`. |
| `format.R` | Column formatting (`format_column`/`format_one_num`), initial sizing (`cal_column_width`/`height_of`), alignment/merge validation (`valid_align`/`valid_merged_cell`), kable reverse-parse, `pandoc_wrap`, the `set_attr` DSL parser. |
| `occupancy.R` | **Geometry + sizing core.** The occupancy map and the two forward-pass size computations. |
| `render.R` | **Local-decision renderer + the GridTable adapter.** `border_line`/`content_line`/`pad`, `grid_inputs()`, and the exported `toString.GridTable`/`print.GridTable`. |
| `utils.R` | Small helpers (`str_width`, `minmax`, `is_overlaped`, `substr_width`, …). |
| `constants.R` | `SYMBOL` (box-drawing chars) and `MERGED_CELL_OPTION` defaults. |

`man/` is regenerated by roxygen2; do not hand-edit it.

## Architecture

The engine is an **occupancy-map renderer**: top-down, with every border
character decided locally. There is no per-cell edge geometry and no edge-merge
step. Read the pipeline in this order:

1. **Construction** — `GridTable(data, align, header, footer, ...)` coerces to
   `data.table`, formats every column (`format_column` / `format_one_num`),
   prepends the column names as row 1 when `header` is unset (so user-facing row
   indices then start at 2 for the first data row), and attaches all render
   state as attributes via `data.table::setattr`: `height`, `width` (per-column
   display widths), `align` (`l`/`r`/`c`), `header` (row index of the header
   separator), `footer`, plus optional `caption` and `merged_cells`.
   `kable_to_grid()` is the alternate constructor: it reverse-parses a kable's
   separator line to recover column boundaries (`column_start_end_points`) and
   slices each line by display width (`substr_width`).

2. **Adapter — `grid_inputs(gtable)` (render.R).** Reshapes the `GridTable` into
   the core's inputs:
   - cell text → a character matrix; each merged region's members are folded
     into the anchor (top-left) cell — joined column-major with `\n` unless
     `drop_content`, in which case only the anchor's own text is kept — and the
     covered positions are blanked;
   - blank / `&nbsp;` lines are dropped from every cell; `wrap` regions get
     pandoc continuation `\` appended (via `pandoc_wrap`);
   - `merged_cells` (a named list of `{rows, cols, drop_content, middle, wrap}`)
     → integer `c(r1, c1, r2, c2)` rectangles, plus a logical `middle` matrix;
   - `header` (row index) and `footer` (row indices) → **rule gap indices**: a
     footer at row `N` becomes a `=` rule above row `N` (gap `N-1`) and along the
     table bottom (gap `nrow`).

3. **Occupancy map — `build_occupancy(nrow, ncol, merges)` (occupancy.R).**
   `anchor_row`/`anchor_col` record, for every position, which cell owns it (its
   top-left corner); `last_row`/`last_col` record, at each anchor, how far the
   cell spans. The whole renderer is built on one predicate:
   `occ_same_cell(occ, r1, c1, r2, c2)` — "do these two positions belong to the
   same cell?" (off-grid counts as a different cell, so the outer rectangle is
   always a border).

4. **Forward-pass sizing (occupancy.R).** `compute_field` (column widths) and
   `compute_height` (row heights) each make one pass: single-cell tracks are set
   directly, then spanning cells are processed narrowest-span-first and
   `grow_to_fit` only enlarges a span's tracks when its content does not already
   fit. Seeded from `set_attr`/`cal_column_width`/`height_of` as a floor (taken
   as `max`). **All sizing is computed up front — there is no resize retry.**

5. **Rendering (render.R).** `occupancy_render` interleaves `border_line` (one
   rule per row gap) with each row's `content_line`s. `border_line` decides each
   character locally via `occ_same_cell`: `+` where a vertical border meets the
   rule, fill (`-`, or `=` on a header/footer rule, with alignment `:` colons)
   where a horizontal border runs, and a space where a rowspan crosses
   uninterrupted. `content_line` walks a row left to right, grouping same-cell
   columns (a colspan) into one padded field; `pad` applies the per-column
   alignment to the **body** text, and a `middle` anchor reserves leading blank
   lines to centre vertically. `toString.GridTable` prepends any `caption`;
   `print.GridTable` `cat`s the result.

### A note on the rowspan model

A rowspan's *internal* horizontal border lines are **structural blanks** — the
renderer always draws them (blank in the spanning column) and only places text
on each row's own lines. So `compute_height` calls `grow_to_fit` with
`absorbed_borders = 0`: counting those borders as usable height (as the
reference renderer did) over-estimates the room and silently drops the cell's
last line(s). Column widths are the opposite: a colspan's internal `|` columns
*are* absorbed into the content field, so `compute_field` uses
`absorbed_borders = lc - col`.

## Attribute mutation & the `set_attr` DSL

Because the table is a `data.table`, all state changes go through
`data.table::setattr` (by reference). `set_attr()` / the `...` of `GridTable()`
expose a small adjustment DSL for `width` and `height`: pass a numeric vector to
set absolutely, or a string like `"2/2"`, `"2+1"`, `"b-3"`, `"B/2"` to adjust an
existing value. `parse_number_adjust` reads it as `<index><op><operand>` where
the index may be a number or a letter (`A`=1, `B`=2, …) and the op is one of
`+ - * / =`. `merge_cells()` registers/cancels merged regions (options
`drop_content`, `middle`, `wrap`) as a named list attribute; it validates the
region (`valid_merged_cell`, which forbids a region straddling the header rule)
and rejects overlaps.

## Tests

`tests/testthat/` is the regression net:

- `test-snapshot.R` — **golden-master rendered output** for every representative
  scenario (simple, colspan, rowspan, row+col merge, CJK, footer, caption,
  multi-line growth, wrap, drop_content, `kable_to_grid`, `set_attr` DSL). A
  visual change anywhere in the pipeline fails here. When you change the engine
  deliberately, eyeball each diff and rebaseline with `snapshot_accept`; a
  *structural* break (misaligned borders) is a bug, not a rebaseline.
- `test-occupancy.R` — the geometry/sizing core (anchor matrices, `same_cell`,
  the two forward passes, the rowspan content-fit regression).
- `test-render.R` — `pad`, a few `border_line` decisions, and `grid_inputs`
  reshaping (footer-gap mapping, merge folding, `drop_content`, the `middle`
  matrix).
- `test-api.R` / `test-format.R` / `test-utils.R` / `test-gridtable.R` —
  constructors, formatting helpers, utilities, and a small end-to-end set.

## Gotchas

- **Snapshot tests are skipped under CRAN emulation.** A plain non-interactive
  `Rscript -e 'devtools::test()'` reports the rendering snapshots as "skipped (On
  CRAN)". Set `NOT_CRAN=true` to actually exercise them.
- **`GridTable(header = NULL)` shifts user row indices.** It prepends the column
  names as row 1, so the first *data* row is row 2 — `merge_cells(i = 2:3, ...)`
  targets the first two data rows, not the header.
- **Body alignment is real now.** `pad` honours each column's `align` for body
  text (not just the header rule's colons). Numeric columns default to `r`.
- **Most functions are internal.** Only `GridTable`, `kable_to_grid`,
  `merge_cells`, `set_attr`, `print.GridTable`, `toString.GridTable` are
  exported. Reach the rest via `devtools::load_all()`.
